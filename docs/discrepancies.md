# Source and prototype differences

- The user's six-page Expande brand manual now overrides the original prototype's teal/orange identity. Exact vector logo variants, original X/plus motifs, the manual's embedded RGB colours and locally served Rubik are used throughout the app. Original content media and flows remain; app-specific spacing, neutral surfaces and functional status colours are documented adaptations. See [brand implementation](brand-implementation.md).

- By explicit request, challenge tracking now depends on catalogue origin. Expande challenges expose automatic demo tracking and read-only Expande states; market challenges expose a preselected manual record whose state, business stage, result and notes are maintained by the visitor's company. Server actions enforce both boundaries. This narrows the original generic “Seguir desafío” action without claiming a real Expande or third-party integration.

- Financing was changed by request to a single library of twelve researched real programmes, with local illustrations, article sections, review dates and official exits. Thirteen earlier records are hidden from discovery while their IDs and saved links remain readable as archived entries. Programme information is separate from current call status; only BIG13 was verified open at review, and its precise deadline uses real time rather than the visitor clock. Runtime optional fields support this without altering the immutable source package. Provenance badges and source sections are hidden on financing routes. See [funding library](financiamiento-library.md).

- Calendar event cards and details now show thematic illustrations by user request. All 38 original events retain dates, precision, organisers, costs, registration links and provenance; only optional runtime thumbnail fields were added. Documentary badges and detail source sections are hidden on calendar routes. Demo labels, tentative dates and reminder restrictions remain. See [calendar thumbnails](calendario-thumbnails.md).

- Innovación was enriched by request to 15 illustrated articles (five cases, five news, five trends). Runtime optional thumbnail, article-section and reference fields preserve compatibility with original records. Documentary facts and qualifiers remain; the two new cases describe proposed pilots without measured achievements or named real operators. Innovation routes hide provenance badges and source sections as requested while retaining metadata internally. See [innovation library](innovacion-library.md).

- Figma uses a single interactive code layer instead of a frame for each screen. Screen IDs V01–V26/C01/C02 therefore come from the source specification.
- The originally inspected UI read “Mis postulaciones” and used a teal/orange palette; the later brand-manual request replaces that palette. The original prototype displays four open challenges by default; the requested catalogue update now starts `/desafios` with all states so the five documentary challenges are visible. Home recommendations still use the open-challenge default.
- The original package persisted browser state only. The local app replaces it with SQLite, independent visitor sessions, server validation and agent editing.
- Shared catalog records remain live across visitors; organization/user/activity records are copied from templates into each new session. Resetting a session uses current templates and does not restore the catalog.
- The fixed clock is November 6, 2026, matching the specification; wall-clock audit timestamps remain actual timestamps.
- Metadata-only document simulation is intentional. Real source URLs require a visible exit confirmation and may be unavailable; no availability or current opportunity status is asserted.
- Full live inspection of nested Figma controls is blocked by unavailable source-resource reads and Windows access errors. Uninspected interactions are implemented from the complete specification, not represented as visually verified Figma matches.
- Runtime application snapshots allow an unknown (`null`) TRL rather than inventing a value when a newly added solution has no TRL. The original source schema is preserved unchanged; this is a documented runtime extension.
- Personal profiles include an optional string `last_name` (“Apellidos”) in the runtime user contract. Existing names are preserved without guessing or splitting surnames; records without this field remain valid. The original source schema and seed are unchanged.
- Formación was enriched by request to 12 illustrated cards (8 cápsulas, 3 masterclasses, 1 documentary recap). Optional runtime learning fields `thumbnail_url`, `thumbnail_alt` and `reference_source_ids` support local images and additional validated editorial sources. Lesson durations/outlines remain illustrative and playback is simulated; the original recap metadata is preserved. See `formacion-library.md` for the source manifest, artwork prompts, catalogue batch and verification.
- Effective dates for fictitious open/upcoming challenges and expired funding calls are calculated against each visitor's demo clock. Changing that clock does not rewrite the shared catalog. Documentary records are never automatically labeled currently open.
- By explicit request, LEARN-R01 now plays the user-provided MP4 inline. It is a byte-identical local copy with H.264/AAC and a measured duration of 47.76 seconds, replacing its playback URL while retaining the original source attribution. Other training playback remains simulated. No video upload service or external hosting was introduced.
- The five documentary challenges (CH-R01–CH-R05) were enriched from their supplied PDF briefs through the catalog CLI on 2026-11-08. Existing IDs, PDF source references, planned stages, dates and unknown values were retained. AMSA calls remain `por_confirmar`; the two Codelco 2025 calls remain `cerrado`. ABC Dust is a proposal and was excluded from this catalogue update.
